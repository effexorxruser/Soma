# CONTRIBUTING

Спасибо за интерес к Soma.

## Прежде чем начать

1. Прочитайте `README.md`, `docs/architecture.md`, `docs/development.md` и `docs/safety.md`.
2. Убедитесь, что изменение соответствует safety-first контракту.
3. Не расширяйте product scope без явного обсуждения.

## Локальный запуск

```bash
npm install
cp .env.example .env
npm run dev
```

Основные проверки:

```bash
npm run lint
npm run test
npm run build
npm run check
```

## Процесс внесения изменений

1. Сделайте небольшое фокусное изменение.
2. Обновите документацию, если меняется поведение или интерфейс.
3. Запустите quality gates локально.
4. Откройте PR по шаблону и кратко опишите:
   - что изменено;
   - зачем;
   - какие проверки пройдены;
   - какие риски есть.

## Обязательные инварианты (нельзя ломать)

- Transport-слой не принимает policy-решения.
- Любой user-facing response path проходит через policy-first contract.
- Сохраняются deterministic priorities classifier.
- Запрещена имитация медицинской/клинической или кризисной помощи.
- Honest limits: не добавлять обещаний того, чего нет в коде.

## Требования к тестам

- Любое изменение classifier/policy требует обновления tabular regression suite в `tests/services/safety/policy.test.ts`.
- Любые изменения env/config должны сопровождаться тестами в `tests/config/env.test.ts` (или эквивалентным покрытием).
- PR без релевантного покрытия может быть отклонен.

## Стиль и коммуникация

- User-facing и docs слой — на русском языке (кроме стандартных технических терминов).
- Тон: спокойный, честный, без маркетинговой гиперболы.
- Коммиты: ясные и предметные.
